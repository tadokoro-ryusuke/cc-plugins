# レンダリングした現物の取得と、表示条件ごとの確認手順

SKILL.md の Step 0(現物の取得)と Step 6(表示条件ごとの確認)の具体的な手順。判定の基準と Must / Should の対応は SKILL.md が正本で、ここには「どうやって確かめるか」だけを置く。

基準の出典: WCAG 2.2(https://www.w3.org/TR/WCAG22/ 、2026-10-26 確認)。

## 1. 現物を取る

Web の UI は、実際のブラウザでレンダリングしたものを審査する。

- 使う道具: ブラウザ MCP(Playwright / Claude in Chrome など)か、手元のブラウザ。画面幅の変更、メディア特性(`prefers-color-scheme`・`prefers-reduced-motion`)の切り替え、スクリーンショット、ページ内での JavaScript 実行ができるものを選ぶ。
- 取る画面幅は3つ。
  - プロジェクトがサポートする最小幅。指定がなければ **320 CSS px**(1.4.10 の検証幅。1280px の画面を 400% に拡大したのと同じ幅)。
  - 中間の幅。Tailwind を使っているなら md(768px)前後。
  - デスクトップの幅(1280px など)。
- ダークモードに対応しているなら、ライトとダークの両方を取る。`prefers-color-scheme` で切り替わるサイトはメディア特性を切り替え、`.dark` クラスで切り替わるサイト(shadcn/ui の既定)はテーマの切り替え操作か、`<html>` へのクラス付与で切り替える。
- 取得のたびに記録する: URL(またはコミット)、ブラウザと版、画面幅、カラースキーム、reduced motion の設定、取得日。

### 「レンダリング未確認」の扱い

WebFetch のような要約型の取得ツールや、ソースコードだけで審査したときは、報告の冒頭に **「レンダリング未確認」** と書く。

- そのときは、色・余白・重なり・はみ出しなど見た目の指摘と、「AA 適合」の主張の根拠にしない。
- 指摘できるのは、ソースから決定的に分かること(`alt` の有無、`label` の関連付け、`outline: none`、トークンの値によるコントラスト比など)に限る。
- なぜ: 要約型のツールはページを小型モデルが要約した結果を返すので、レイアウトや色を再現しない。ソースだけでは、カスケードの結果や画面幅ごとの崩れが分からない。

## 2. 表示条件ごとの確かめ方

### 1.4.10 Reflow(AA): 最小幅で横スクロールが要らないか

1. 画面幅を最小幅(既定 320 CSS px)にする。
2. ページ全体の横はみ出しを調べる。ページ内で次を実行し、`true` なら横スクロールが出ている。

   ```js
   document.documentElement.scrollWidth > document.documentElement.clientWidth
   ```

3. この式はページ全体しか見ない。ページを上から下までスクロールし、要素の内側だけがはみ出している箇所(切れた文字、画面外に出たボタン)もスクリーンショットで確かめる。
4. データ表・地図・図・動画・ツールバーを表示したまま操作する UI のように、2次元の配置が意味上必要な部分は、その部分だけの横スクロールを許す(1.4.10 の例外)。業務システムの一覧表を誤って指摘しない。

### 1.4.4 Resize Text(AA): 200% でも内容・機能を失わないか

1. ブラウザのズームを 200% にする。
2. 文字の切れ・重なり、隠れて押せないボタン、読めなくなったラベルがないかを見る。
3. ブラウザ MCP でズームを操作できないときは、ルート要素の `font-size` を2倍にした状態で代用し、「代用」と記録する。px で固定した文字は大きくならないので、それ自体を指摘の候補にする。

### 1.4.12 Text Spacing(AA): 間隔を広げても内容・機能を失わないか

基準の値どおりに上書きする CSS をページに足し、文字の切れ・重なり・はみ出しがないかを見る。

```css
* {
  line-height: 1.5 !important;      /* 行の高さ: 文字サイズの 1.5 倍 */
  letter-spacing: 0.12em !important; /* 文字間隔: 0.12 倍 */
  word-spacing: 0.16em !important;   /* 単語間隔: 0.16 倍 */
}
p {
  margin-bottom: 2em !important;     /* 段落の後: 2 倍 */
}
```

- 和文のように、語の間を空白で区切らない書記体系では、存在しない性質を除いて判断してよい(1.4.12 の例外規定)。欧文が混じる箇所では単語間隔も確かめる。
- 高さを固定したボタン・バッジ・カードで、文字がはみ出して切れていないかを重点的に見る。

### 2.4.11 Focus Not Obscured (Minimum)(AA): フォーカスが完全に隠れないか

1. 固定ヘッダ・固定フッタ・チャットのウィジェット・Cookie バナー・追従する CTA など、画面に固定して置いた要素がある画面を選ぶ。
2. 各画面幅で、ページの先頭から Tab キーで末尾まで進む。Shift+Tab で戻る方向も確かめる。
3. フォーカスした要素が、固定要素に **完全に** 隠れる位置がないかを見る。一部が隠れるのは AA では違反ではない(完全に見えることを求めるのは 2.4.12 で AAA)。
4. 利用者が開いたもの(メニューなど)がフォーカスを覆っても、フォーカスを先に進めずに隠れた要素を見える状態に戻せる(閉じられる)なら、違反にしない(2.4.11 の注記2)。
5. よくある直し方: `scroll-padding-top` / `scroll-padding-bottom` に固定要素の高さを入れる(WCAG の達成方法 C43。https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html 、2026-10-26 確認)。

### 2.2.2 Pause, Stop, Hide(A)と 2.3.1 Three Flashes(A)

- 自動で始まり、5秒を超えて続き、ほかのコンテンツと並んで表示される動き(カルーセルの自動送り、背景動画、流れるテキスト)に、一時停止・停止・非表示のどれかの手段があるかを確かめる。自動で更新される情報(ティッカー、ライブのフィード)も、止めるか更新の頻度を変えられる必要がある。
- 1秒に3回を超えて光る表現がないかを確かめる。疑わしいときは録画して数える。

### reduced motion(Should)

1. `prefers-reduced-motion: reduce` を有効にして再読み込みする。
2. 移動・拡大・視差の演出が止まっているかを見る。
3. 押した・開いた・送信に失敗した、といった状態の変化が、まだ目で分かるかを見る。一律 0ms にしてフィードバックまで消えていたら指摘する。
4. インタラクションで起きるアニメーションを止められることは 2.3.3 で AAA なので、AA の Must にはしない。

### ダークモード(Should。コントラストの下限割れは Must)

1. ライトとダークのスクリーンショットを並べ、色の反転ではなくトークンの再割り当てで作られているかを見る(画像・ロゴ・影の破綻、反転した写真)。
2. `color-scheme` が指定され、フォーム部品やスクロールバーなどブラウザが描く部分もモードに合っているかを見る。CSS Color Adjustment の仕様は、作り手が直接制御できないこれらの部分のために `color-scheme` を設けている(https://www.w3.org/TR/css-color-adjust-1/ 、2026-10-26 確認)。
3. 両モードの全ペアのコントラスト比を、SKILL.md の Step 3 に書いたコマンド(ui-visual-defaults の `scripts/contrast.mjs`)で計算する。
