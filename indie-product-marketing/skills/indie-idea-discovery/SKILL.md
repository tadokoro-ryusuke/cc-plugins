# Indie Idea Discovery — 個人開発プロダクトの機会発見

解決策を提案する前に、解く価値のある課題を見つける。創業者固有の証拠、現在の市場の証拠、構造化した発散、独立した評価を組み合わせる。流行りのアプリのアイデアを並べただけの汎用的なリストは返さない。

Claude Code で Web から証拠を集めるとき、発散パスや採点を別の文脈に分けるとき、インタビューの依頼・投稿・公開・出稿などで外部へ働きかけるとき、または他のスキルや dev-core へ引き継ぐときは、[references/claude-code-runtime.md](references/claude-code-runtime.md) を読む。

## 発見モードを選ぶ

依頼に合う、最も狭いモードを選ぶ。

1. **創業者起点の発見（founder-first discovery）** — 隣接する課題を調べる前に、創業者の経験、繰り返している作業、アクセスできる相手、資産、制約、他者にない強みを棚卸しする。
2. **領域起点の発見（domain-first discovery）** — 1つの市場・職業・コミュニティ・ワークフロー・生活状況を調べ、満たされていないニーズと弱い代替手段を探す。
3. **摩擦の採掘（friction mining）** — レビュー、サポートのスレッド、回避策、手作業のプロセス、支出、途中で放棄されたタスクを分析し、機会のシグナルを探す。
4. **コンセプトの展開（concept expansion）** — 「メモアプリ」や「看護師向けのツール」のような1つの種から、意味のある違いを持つ解決の方向性を作る。
5. **ポートフォリオ選定（portfolio selection）** — 既存のアイデア群を、証拠・ハードゲート・創業者の目的を使って重複を除き、比較し、順位を付ける。
6. **アイデア監査（idea audit）** — アイデア出しの方法や出力にある、裏付けのない前提、模倣、AI による収束、選択バイアス、安全上のリスク、欠けている検証を特定する。

モードは文脈から推定する。探索空間を大きく変える情報だけを質問し、それ以外は前提を明示して進める。

選んだモードを前に進めるフェーズを使う。提供された調査と候補は再利用する。監査やポートフォリオの比較では、新しいアイデアを生成せずに、証拠の確認と評価へ直接進んでよい。

## 証拠と想像を分ける

重要な記述を次のように分類する。

- **観察事実（Observed fact）** — 直接提供された行動・分析データ・支出・ワークフロー、または検証済みの公開された事実。
- **報告された事実（Reported fact）** — ユーザー・創業者・レビュアー・事例研究が報告しているが、独立に検証されていないもの。
- **推論（Inference）** — 特定した証拠と前提から導いた結論。
- **機会仮説（Opportunity hypothesis）** — まだテストが必要な、課題・顧客・事業についての主張。
- **コンセプト（Concept）** — 考えられるプロダクトとしての応答。機会が存在する証拠ではない。
- **推奨（Recommendation）** — 証拠と不確実性によって正当化される次の行動。

現在の市場調査を求められたら、最新のソースを参照し、重要な主張には出典を付ける。公式文書、当事者自身の製品ページと価格ページ、観察できる顧客行動、生のユーザー調査、査読付きの研究を優先する。AI による要約、汎用的なアイデア一覧、SEO 向けのページ、根拠の説明がない市場規模の主張は、弱い入力として扱う。

元になった動画を使うとき、組み合わせの手法が機能する理由を説明するとき、AI によるアイデア出しを評価するとき、または関心と需要を区別するときは、[references/evidence-and-video-audit.md](references/evidence-and-video-audit.md) を読む。

## フェーズ1: 創業者の探索空間を枠付けする

次を把握する。

- スキル、領域の経験、資格、所属するコミュニティ。
- 日次・週次・季節ごと・出来事をきっかけに繰り返している行動。
- スプレッドシート、スクリプト、プロンプト、メモ、手作業のサービスで既に作っている回避策。
- 摩擦を取り除くために使っている購入品、サブスクリプション、外注先、ツール。
- 広い注目を買わなくても創業者が届く相手。
- 独自の、または許諾を得たデータ・コンテンツ・ワークフロー・連携・信頼。
- 望む顧客、ビジネスモデル、販売の進め方、地域、言語。
- 時間・資金・プラットフォーム・運用・サポート・規制の制約。
- 収益目標、望む生活スタイル、創業者がやらないと決めている仕事。

すべての機会を創業者起点に限定しない。創業者の文脈は、判断・アクセス・コミットメントを高めるために使い、そのうえで他の人も同じ課題を抱えているかを確かめる。

ユーザーが残しておける発見ブリーフを求めるときは `assets/founder-inventory.md` を使う。インタビューの問いと行動の棚卸しの方法は [references/discovery-methods.md](references/discovery-methods.md) を読む。

## フェーズ2: 解決策より先に課題を掘る

行動とその結果の証拠を探す。

- 特定の状況に結びついた、繰り返される不満。
- 手作業によるコピー、突き合わせ、リマインド、承認、日程調整、報告。
- 代替手段として使われているスプレッドシート、個人のスクリプト、テンプレート、人手のサービス。
- 既存の購入、予算、外注の仕事、乗り換えの行動。
- 放棄されたタスク、遅延、手戻り、ミス、逃した売上、罰則、感情的な負担。
- ジョブ、回避策、うまくいかなかった結果を記述しているプロダクトレビュー。
- サポート、ドキュメント、コミュニティ、調達、求人票に表れる証拠。
- 以前は弱かった解決策を実現可能にする、技術・規制・プラットフォーム・人口構成・コストの新しい変化。

機能要望、検索ボリューム、大きな市場規模、SNS での反応、創業者1人の不満を、十分な証明として扱わない。出典、日付、セグメント、行動、結果を `assets/problem-evidence-ledger.md` に記録する。

有望なシグナルは、それぞれ課題文に変換する。

> **[具体的な行為者]** が **[きっかけとなる状況]** で **[進めたいこと]** をしようとするが **[摩擦]** があり、そのため **[代替手段]** を使って **[時間・お金・リスク・感情の負担]** を負っている。

機能や属性（デモグラフィック）だけを述べている文は採用しない。

## フェーズ3: 収束する前に独立して生成する

規模の大きい発見やコンセプトの展開では、異なる証拠やメカニズムを引き出せる場合に、生成パスを分けて使う。次から選ぶ。

1. **創業者の種パス（founder seed pass）** — AI の提案を加える前に、創業者が自力で挙げた課題とコンセプトをそのまま残す。創業者の経験が得られないときに、それを捏造しない。
2. **証拠主導パス（evidence-led pass）** — 検証済みの課題カードだけに対して応答を生成する。
3. **構造化した組み合わせパス（structured combination pass）** — 形態分析マトリクス（morphological matrix）で、明示した次元を変化させる。

面倒な作業、運用、規制対象、移行、コンプライアンス、突き合わせ、サービスの比重が大きい課題を見落としそうなときは、**地味な課題のパス（unsexy pass）** を使う。

先に出たアイデアが後の出力のアンカーになるような、1つの伸び続ける会話の中で全パスを生成しない。可能な範囲で前の候補を伏せ、証拠や次元を意図的に変え、独立したパスが終わってからだけ統合する。

## 形態分析マトリクスを正しく使う

まず課題を定義し、それから次のような次元を行または列にする。

- 行為者または支払者。
- きっかけとなる状況と頻度。
- 入力とデータソース。
- 出力とユーザーにとっての成果。
- 操作の形態。
- 時間・量・可視性・プライバシーの制約。
- 1人用、協働、マーケットプレイス、ネットワークのいずれの構造か。
- 自動化の度合い。
- 提供面と獲得チャネル。
- 価格と支払いのタイミング。
- 別の業界からの類推。

ユーザーの成果を改善する、筋の通った組み合わせを生成する。全組み合わせ（直積）を作ったり、有用性のない新しさを評価したりしない。作業用の表には `assets/morphological-matrix.md` を使う。変化の操作子、多様性の管理、例は [references/divergence-and-morphology.md](references/divergence-and-morphology.md) を読む。

## フェーズ4: クラスタにまとめ、表面的な変種を取り除く

すべての候補を次の形に正規化する。

`顧客 + きっかけ + 課題 + 約束する成果 + メカニズム + 支払者`（customer + trigger + problem + promised outcome + mechanism + payer）

そのうえで、次を行う。

- 名前、見た目のスタイル、AI の言い回しだけが違うアイデアは統合する。
- 顧客、きっかけ、経済性、メカニズムが意味のある形で異なるものは分けておく。
- 直接の模倣、汎用品のラッパー、明確な切り口（wedge）のないコンセプトに印を付ける。
- 飽和したカテゴリは、カテゴリ全体を使えないと断定せず、課題とセグメントの単位で地図にする。
- ばらつきの大きい外れ値を少数残し、評価に回す。

作り込んだモックアップが、より強い課題の証拠より上位にならないようにする。

## フェーズ5: 証拠とハードゲートで評価する

候補の採点は、生成が完了してから行う。コンセプトの見た目の完成度を見せたり評価したりする前に、課題を評価する。

### ハードゲートを適用する

重要なゲートが1つでも不合格なら、構築を推奨しない。

- 本当の課題である証拠がなく、倫理的にすばやく学ぶ方法もない。
- 対象顧客に、創業者の制約の範囲内で届かない。
- コンセプトが、捏造した活動、禁止されたデータ、有害な主張、または受け入れられない安全上のリスクに依存している。
- 創業者が、示された時間と資源の範囲で、最初の価値を届けられない、またはプロダクトを運用できない。
- 継続的な価値、支払いの機会、戦略的な学習価値、または意図して範囲を限定した非営利の目的のいずれも、もっともらしく見込めない。

### 残った候補を比較する

各次元を 0〜5 で評価し、証拠のグレードと不確実性のメモを付ける。

- 課題の証拠、頻度、緊急性、結果の重さ。
- 現在の支出、またはコストの高い代替手段。
- 到達可能性と、流通（ディストリビューション）の前提。
- 創業者の洞察、アクセス、信頼性、持久力。
- 狭い参入の切り口と、最初の価値が出るまでの時間。
- 繰り返し使われる仕組み、または拡大の仕組み。
- 支払者、価格の論理、利益率、運用の負担。
- 技術的な実現可能性と、学習にかかる時間。
- 競合との差別化と、蓄積していく優位性。
- 信頼、プライバシー、安全、規制、モデレーション、プラットフォームのリスク。

ハードゲートの不合格を加重合計の中に隠さない。LLM の確信度や自己採点を市場の証拠として使わない。万能の重みを作り出さず、同点の決着にはユーザーの目的を使う。

評価基準の全体、判定ルール、ポートフォリオの作り方は [references/evaluation-and-handoff.md](references/evaluation-and-handoff.md) を読む。残しておく成果物には `assets/opportunity-card.md` と `assets/idea-portfolio.md` を使う。

## フェーズ6: コミットではなく学習を選ぶ

上位の機会ごとに、次を特定する。

- 顧客・課題・解決策・流通・定着・経済性について、最もリスクの高い前提。
- 最も強い既存の証拠と、欠けていると最も危険な証拠。
- 論旨を反証しうる、最も安く倫理的な行動。
- テストの前に決めておく、合格・修正・停止のルール。
- 見直しまでに使ってよい資金と創業者の時間の上限。

より強いシグナルを優先する。

`コンテンツの閲覧 < クリック < メールアドレスの登録 < 条件に合う相手との会話 < 観察したワークフロー < プロトタイプの利用 < デポジットや予約注文 < 繰り返しの利用 < 有料での継続`

モックアップ、SNS での反応、広告のクリック、ウェイトリストは、メッセージへの関心の証拠として扱い、定着や事業が成り立つことの証明とはしない。

## 選んだ機会を引き継ぐ

候補の絞り込みを求められたら、意思決定に使える状態の機会で締めくくる。選んだ機会ごとに、関係する引き継ぎ情報を含める。

- 顧客、きっかけ、ジョブ、結果。
- 現在の代替手段とその証拠。
- 提案する約束とメカニズム。
- 創業者の優位性と、届くチャネル。
- 継続的な価値と支払者の仮説。
- 最もリスクの高い前提。
- 最初の検証と停止ルール。
- 証拠台帳と未解決の問い。

依頼に検証やローンチの作業も含まれているときは、利用できれば `indie-product-marketing:indie-product-marketing` を使ってその作業に進む。証拠、前提、判定ルールを引き継ぎ、依頼された作業が残っているのに引き継ぎの段階で止めない。発見だけの依頼では、より広いキャンペーンを始めずに、次の検証行動を特定する。引き継ぎを文書として残すと役立つときは `assets/validation-handoff.md` を使う。

## 意思決定に使える成果物を出す

選んだモードに必要な最小限の成果物を、次の中から選んで返す。

1. **発見ブリーフ** — 創業者の制約、探索の範囲、前提、目的。
2. **証拠マップ** — 観察事実、報告された事実、推論、欠けている情報、ソースの質。
3. **課題の全体像** — クラスタにまとめた課題文と、除外した偽のシグナル。
4. **発散の記録** — 独立したパス、マトリクスの次元、重複の管理。
5. **機会ポートフォリオ** — 正規化したコンセプトと、そのハードゲート、スコア、確信度、トレードオフ。
6. **上位の機会カード** — 通常は3件。証拠がそれより少ない件数しか支持しなければ減らす。
7. **検証キュー** — 最終候補ごとの、最もリスクの高い前提、テスト、予算、期間、判定ルール。
8. **推奨** — 進める・さらに調べる・保留する・却下する、とその理由。

リストを水増しせず、証拠の強いアイデアを少なく返す。調査で信頼できる機会が見つからなければ、確信を作り出さずにそう伝え、次に探すべき発見の対象を推奨する。
