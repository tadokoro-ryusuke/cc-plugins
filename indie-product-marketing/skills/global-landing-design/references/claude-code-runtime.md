# Claude Code での実行ノート（global-landing-design）

このファイルは cc-plugins が所有する。SKILL.md は codex-plugins の正本からの翻案で、同じスキルの他の references と assets は英語原文のコピー。Claude Code に固有の実行指示は、ここにだけ置く。

## スキルの呼び名

同じプラグインの他のスキルは、`indie-product-marketing:<skill>` の名前で参照する。より広い集客やローンチの計画は `indie-product-marketing:indie-product-marketing` に渡す。

## 参考サイトの証拠

SKILL.md の手順 2 の区別（スクリーンショット、観察したインタラクション、マーケティング上の主張、測定された成果）を、ツールの性質に合わせて守る。

- WebFetch は、小型モデルがページを要約した結果を返す。コピーやセクション構成の把握には使えるが、色・レイアウト・モーション・インタラクションといった見た目の主張の根拠にはしない。
- 見た目の主張は、ブラウザ MCP（Playwright / Claude in Chrome）でレンダリングしたページで確かめ、画面幅と取得日を記録する。ブラウザ MCP が使えないとき、またはレンダリングに失敗したときは、手順 2 のとおり「テキストのみ」と明記する。
- 数値・引用・価格・規約の文言は、生のソース（ブラウザ MCP のページテキスト、curl で取得した本文など）で照合する。照合できなければ、参考サイトの記録（手順 2 の表）に「要約経由・未照合」と書く。
- WebSearch は US-only のため、日本市場の参考サイトや一次情報は、既知の一次 URL を直接取得する。
- すべての観察に取得日を付ける。ログインや有料の制限は回避せず、手順 2 のとおりアクセスの制限として記録する。

## 外部アクションの境界

Claude Code では、ブラウザ MCP、CLI（`gh`、`wrangler` など）、クラウドの MCP から、次の操作を実際に実行できてしまう。そのため境界をここで明文化する。

ローカルでの構築、下書き、検証は進めてよい。次の操作は、ユーザーの明示の指示があるときだけ行う。

- デプロイ、DNS の変更、インデックス公開に関わる変更（robots、sitemap、noindex の解除など）
- Artifact の公開リンク化（Artifact は既定で非公開。他社のブランドや画面を自社のものとして再現したページは、手順 2 のとおりそもそも作らない）
- ウェイトリストなどへのメール送信
- 決済の設定・有効化
- Product Hunt やデザインギャラリーへの掲載
- LP の告知を含む公開投稿・DM・リプライ・いいね
- 出稿・課金（需要実験の流入を含む）

一括・自動のエンゲージメント（自動いいね、一括 DM など）は、指示があっても行わない。

ローカルのページ、Artifact、モックアップを「デプロイ済み」「公開済み」と報告しない。需要の証拠としても数えない（手順 7 の3つの結論を分ける）。

## LP の検証

- まずプロジェクト既存のチェックを使う。dev-core が導入されていれば `dev-core:verify` を使う。verify が扱うのはビルド・型・lint・テストなどで、レイアウト、キーボード操作、言語切り替えは次の手順で別に確かめる。
- ブラウザ MCP（Playwright / Claude in Chrome）があれば、次を確かめる。
  - 複数の画面幅。サポートする最も狭い幅と、各言語の長いテキストの状態を含める。
  - 変更したインタラクティブなコンポーネントのキーボード操作とフォーカス（ダイアログを閉じたあとのフォーカスの戻り先など）。
  - 言語切り替えと、各言語のページへの経路。
  - 約束した主要な行動（デモ、ダウンロード、送信など）。
  - モーションを追加したなら、reduced motion の設定での表示。
- 実行したブラウザと画面幅を記録する。スクリーンショットやアニメーションのプレビューだけで、操作の検証を済ませたことにしない。
- ブラウザ MCP がないとき、または確かめられなかった項目は「未検証」と明記する。

## 他のスキルとの棲み分け

- LP の主担当は本スキル（論旨・証拠・ローカライズ・検証）。`ui-ux-pro-max:ui-ux-pro-max` と `frontend-design:frontend-design` は、導入されていれば、配色・フォント・スタイルの参照の補助として手順 4 で使う。合意済みのブランドを上書きしない。
- `design-core:design-review` は見た目とアクセシビリティの審査、`design-core:ui-visual-defaults` はブランドのない新規 LP でのデザイントークンの確定を担う（導入されている場合）。本スキルのレビューは、メッセージ・主張・証拠の審査として併用する。
- 個人情報の扱い、表示に関する規制、生成物の権利処理といった法規の深い論点は、compliance-core に任せる（導入されている場合）。
- 受託案件の営業・見積には使わない。
