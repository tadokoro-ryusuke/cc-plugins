# Decision Grill

$ARGUMENTS を、実装前に意思決定モデルが共有できるまで検討する。明確で可逆な通常作業には適用せず、重要な判断だけを深掘りする。

## インタビュー契約

1. リポジトリ、参照ドキュメント、既存設定を先に調査する。
2. 残った不確実性を次の3種類に分類する。
   - **事実**: 環境から確認する。ユーザーに質問しない。
   - **可逆な仮定**: 推奨デフォルトと戻し方を示し、反対がなければ採用する。
   - **重要判断**: スコープ、アーキテクチャ、セキュリティ、不可逆データ、外部副作用、プロダクト意図が変わる場合だけ質問する。
3. 一度に重要な質問を1つだけ提示し、回答を待つ。
4. 各質問には推奨回答、理由、主なトレードオフを添える。実行可能な代替案だけを示す。
5. 回答に応じて判断ツリーを進み、矛盾、失敗モード、隠れた依存を追及する。固定質問票を消化しない。
6. 追加質問が計画を実質的に変えなくなったら終了する。

## 自律性の境界

- 読み取り調査で判明する事実を質問しない。
- 命名や整形など低リスクで可逆な選択をブロッカーにしない。
- 別途依頼されるまで、実装、ファイル変更、Issue作成、commit、push、PR作成を行わない。
- 不明な事実と判断が必要な事項を混同しない。

## 終了時の出力

- 合意した目標と非目標
- 決定事項と理由
- 可逆な仮定とデフォルト
- 残存リスクまたは未決事項
- 権限を越えて実行しない、次の最小アクション
