# Continuous Learning

Mitchell Hashimotoの原則: **「エージェントがミスを犯すたびに、そのミスを二度と起こさない仕組みを作る」**

## 学習ループ

### 1. ミスの検出

セッション中に発生した問題を特定:
- ビルドエラー、テスト失敗、lint違反
- レビューで指摘された設計上の問題
- 繰り返し発生するパターン（同じ種類のバグ、同じ修正手順）

規則にするのは、再発を確認した失敗だけにする。1回限りの失敗、タイポ、TDD で意図した Red、一時的な環境の問題は規則にしない。文章のルールより、回帰テストや既存ツールの設定を優先する。

### 2. 根本原因の分析

問題の原因を分類:
- **ルール不足**: 既存のルール/スキルにガイダンスがない
- **ルール無視**: ルールがあるが遵守されなかった → Hook化を検討
- **知識不足**: プロジェクト固有の制約が記録されていない
- **ツール不足**: 自動検出できるべきエラーが手動チェックに依存

### 3. 防止メカニズムの構築

原因に応じた対策:

| 原因 | 対策 | 保存先 |
|------|------|--------|
| ルール不足 | スキルに追記（理由・適用範囲・追加日・例外の経路を書く） | skills/*/SKILL.md（必要なら references/ に分割） |
| ルール無視 | Hook化（決定的に検出できる範囲の tripwire。多層防御の一層で、完全な境界ではない）。厳密な禁止は permissions.deny と sandbox | hooks/hooks.json + scripts/、利用者の settings |
| 知識不足 | プロジェクト固有設定に記録 | .claude/*.local.md |
| ツール不足 | lint ルール/テスト追加 | eslintrc, テストファイル |

**「祈りベースの指示」を「仕組み」に変える**のが原則。プロンプトに「必ず〜すること」と書いても破られるなら、frontmatter（エージェントの `skills` プリロード等）や Hook（照合できた範囲を止める tripwire）、permissions.deny（厳密な禁止）へ昇格させる。Hook を足したら、止めるべき例と通すべき例の両方をテストする。

文章のルールを足すときは、理由・適用範囲・追加日・例外の経路を書く。例外がありうる操作は「〜しない」で終わらせず、「〜の前に人間の承認を得る」の形にする。理由も例外の経路も無いルールは、例外の無い規則として読まれ、承認済みの作業まで止めることがある。理由と追加日があれば、後の棚卸しで残すか削るかを判断できる。

例: 「`src/gen/` は手で編集せず、生成コマンドで作り直す。手の変更は次の生成で消えるため（対象: `src/gen/`、2026-11 追加）。生成器の不具合で一時的に手で直すときは、先に人間の承認を得る」

### 4. 検証

対策が機能するか確認:
- 同じ操作を試みてブロックされるか（Hook）
- 同じコードを書いた場合にlintで検出されるか
- 次回セッションでルールが参照されるか

### 5. 棚卸し

足したルール・メモ・注意書きは溜まっていく。溜まった注意書きは、要らない承認の要求や定型作業の保留を招く。次のときに見直す。

- 使うモデルを替えたとき（書かれた規則への従い方はモデルで変わる）
- 定期的に（例: 四半期ごと）

削るもの:

- 理由が消えたもの（前提のコード・ツール・運用が無くなった）
- 再現しなくなった失敗に向けたもの
- lint・Hook・テストで強制済みのものと重複する文章のルール

Claude Code では、`/doctor prompt-audit`（2.1.283 以上）で、CLAUDE.md・skills・agents・commands を古いモデル向けの書き方について点検できる。

## 複利的改善

各セッションがハーネスを改善し、改善されたハーネスが次のセッションの信頼性を向上させる。

```
セッション1: バグ発見 → ルール追加
セッション2: ルールが防止 → 新しいバグ発見 → Hook追加
セッション3: Hook+ルールが防止 → より高度な問題に集中
モデル更新時: 棚卸し → 理由の消えたルールと、Hook で強制済みの重複を引退させる
```

## Stopフックとの連携

dev-core の Stop フック（`scripts/stop-quality-gate.sh`）がセッション終了時に以下を自動検出する:

- 変更ファイルに残った `console.log` / `debugger` 等のデバッグ残骸
- テストファイルに追加された focus / skip マーカー（`.only` / `.skip` / `@pytest.mark.skip` 等）と、テストファイルの削除

再発を確認した失敗に限って、ノイズの少ない検出パターンをこのスクリプトに足すことで、Stopフック自体が学習する。
